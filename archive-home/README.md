# 론드 보관소 — 로그인해서 직접 꾸미는 개인 홈페이지

두 캐릭터의 관계와 이야기, 그림과 사진, 함께한 기록을 모아두는 빈티지 자료실 홈페이지입니다.

**이 홈페이지는 코드를 고쳐서 관리하는 사이트가 아니에요.**
승인된 이메일로 로그인한 뒤, 홈페이지 안의 **관리자 페이지(`/admin`)** 에서 글·이미지·메뉴·색상·페이지를 모두 수정합니다.

## 1. 어떻게 동작하나요?

홈페이지는 두 개의 무료 서비스를 함께 씁니다.

| 역할 | 서비스 | 하는 일 |
|---|---|---|
| **화면** | GitHub Pages | 홈페이지 파일(HTML·CSS·JS)을 인터넷에 공개해서 주소를 만들어 줌 |
| **데이터베이스 / 로그인 / 이미지 저장** | Supabase | 글·설정·메뉴 저장, 이메일 로그인, 이미지 파일 보관 |

```
방문자 ──▶ GitHub Pages (홈페이지 화면)
                │  글·이미지·설정 읽기 (누구나)
                ▼
            Supabase ◀── 쓰기·수정·삭제 (승인된 이메일만, 서버가 확인)
```

GitHub Pages만으로는 "로그인"과 "저장"을 할 수 없어서 Supabase를 연결했어요.
**컴퓨터에 설치해야 하는 프로그램은 없습니다.** 모든 과정은 웹 브라우저에서 클릭으로 진행해요.

> 💡 Supabase를 연결하기 전에도 홈페이지는 **데모 모드**로 열립니다.
> 데모 모드에서는 아무 이메일로나 로그인해서 관리자 기능을 체험할 수 있지만, 내용이 **그 브라우저에만** 임시 저장돼요.

## 2. 준비물

- 이메일 주소 1개 (로그인용 — 관리자 이메일이 됩니다)
- **GitHub 계정** (무료) — https://github.com
- **Supabase 계정** (무료) — https://supabase.com
- 이 프로젝트 폴더 (`archive-home`)

## 1단계 — GitHub 가입하고 파일 올리기

### 1-1. GitHub 가입
1. https://github.com 접속 → 오른쪽 위 **Sign up**
2. 이메일, 비밀번호, 아이디(username)를 입력하고 가입
3. 아이디는 홈페이지 주소에 들어갑니다. 예) 아이디가 `nayeon` 이면 → `https://nayeon.github.io/...`

### 1-2. 저장소(Repository) 만들기
1. 로그인 후 오른쪽 위 **+** → **New repository**
2. **Repository name**: 원하는 이름 (영어 소문자 추천). 예) `archive`
3. **Public** 선택 (무료 GitHub Pages는 공개 저장소에서만 됩니다)
4. 나머지는 그대로 두고 **Create repository**

### 1-3. 파일 올리기 (끌어다 놓기)
1. 새로 만든 저장소 화면에서 **uploading an existing file** 링크를 누릅니다.
   (안 보이면 **Add file → Upload files**)
2. 컴퓨터에서 `archive-home` 폴더를 열고, **폴더 안의 내용물 전부**를 선택해서 브라우저 창에 끌어다 놓습니다.
   - `index.html`, `config.js`, `css`, `js`, `assets`, `admin`, `supabase`, `.github`, `.nojekyll`, `README.md` …
   - ⚠️ `archive-home` 폴더 자체가 아니라 **그 안의 내용물**을 올려야 해요. (저장소 첫 화면에 바로 `index.html` 이 보여야 정상)
3. 아래 **Commit changes** 초록 버튼을 누릅니다.

> ⚠️ **`.github` 폴더가 안 올라갔을 때** (Mac은 점(.)으로 시작하는 폴더가 숨겨져 있어서 자주 빠져요)
> 1. 저장소에서 **Add file → Create new file**
> 2. 파일 이름 칸에 `.github/workflows/deploy.yml` 이라고 **그대로** 입력 (슬래시를 입력하면 폴더가 자동으로 생겨요)
> 3. 내 컴퓨터의 `archive-home/.github/workflows/deploy.yml` 파일을 메모장으로 열어 내용을 전부 복사해서 붙여넣기
> 4. **Commit changes**

## 2단계 — GitHub Pages 켜기 (홈페이지 주소 받기)

1. 저장소 위쪽 메뉴에서 **Settings** (톱니바퀴)
2. 왼쪽 메뉴 **Pages**
3. **Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
4. 저장소 위쪽 메뉴 **Actions** 탭으로 이동
   - "홈페이지 배포" 작업이 보이면 누르고 초록색 ✅ 이 될 때까지 1~2분 기다립니다.
   - 아무것도 없다면: 왼쪽 **홈페이지 배포** → 오른쪽 **Run workflow** → **Run workflow**
5. 완료되면 **Settings → Pages** 맨 위에 주소가 나옵니다.
   ```
   Your site is live at https://내아이디.github.io/저장소이름/
   ```
6. 주소를 열어보세요. 빈티지 홈페이지가 **데모 모드**로 보이면 성공! 🎉

📌 이 주소를 메모해 두세요. 5단계에서 씁니다.

## 3단계 — Supabase 가입하고 프로젝트 만들기

1. https://supabase.com → **Start your project** → GitHub 계정으로 로그인하면 편해요.
2. **New project** 를 누릅니다. (처음이면 Organization을 먼저 만들라고 나오는데, 이름만 적고 Free 플랜으로 만드세요)
3. 입력:
   - **Name**: 아무 이름 (예: `archive`)
   - **Database Password**: **Generate a password** 를 누르고, 나온 비밀번호를 안전한 곳에 적어두기 (이 홈페이지 설정에는 쓰지 않지만 나중에 필요할 수 있어요)
   - **Region**: `Northeast Asia (Seoul)` 추천 (한국에서 빠름)
4. **Create new project** → 1~2분 기다리면 준비 완료

## 4단계 — 데이터베이스 표 만들기 + 내 이메일 승인

1. 컴퓨터에서 `supabase/schema.sql` 파일을 메모장(또는 VS Code)으로 엽니다.
2. 아래 줄을 찾아서 **내 이메일**(로그인에 쓸 이메일, 영어 소문자)로 바꿉니다.
   ```sql
   values ('여기에-내-이메일@gmail.com', 'admin', '홈페이지 주인')
   ```
   예) `values ('nayeon@gmail.com', 'admin', '홈페이지 주인')`
3. 파일 내용 **전체**를 복사합니다. (Ctrl + A → Ctrl + C)
4. Supabase 왼쪽 메뉴에서 **SQL Editor** → **New query** (또는 + 버튼)
5. 붙여넣기(Ctrl + V) → 오른쪽 아래 **Run** 클릭
6. 아래에 `Success. No rows returned` 가 나오면 성공입니다.
   - "위험한 작업" 경고창이 뜨면 **Run this query** 를 눌러 진행하세요. (보안 규칙을 새로 설정하기 때문에 뜨는 안내예요)

✅ 이 단계에서 만들어지는 것
- 콘텐츠 표들 (페이지, 종이, 시리즈, 글, 갤러리, 이미지 기록, 사이트 설정)
- `editors` 표 = **승인된 이메일 목록** (내 이메일이 관리자로 들어감)
- 보안 규칙 (방문자는 읽기만, 승인된 이메일만 쓰기)
- 이미지 저장소 `media` (공개 보기, 편집자만 업로드)

## 5단계 — 로그인 설정

비밀번호 없이 **이메일로 받은 링크/코드**로 로그인합니다. 로그인 링크가 내 홈페이지로 돌아오도록 주소를 알려줘야 해요.

1. Supabase 왼쪽 메뉴 **Authentication** → **URL Configuration**
2. **Site URL** 에 2단계에서 받은 홈페이지 주소를 넣고 **Save**
   ```
   https://내아이디.github.io/저장소이름/
   ```
3. **Redirect URLs** → **Add URL** → 같은 주소를 한 번 더 넣고 저장
4. (확인만) **Authentication → Sign In / Providers** 에서 **Email** 이 켜져 있는지 확인 (기본으로 켜져 있어요)

### (선택) 메일에 6자리 숫자 코드도 넣기
휴대폰 메일 앱에서 링크를 누르면 다른 브라우저로 열려 로그인이 안 될 때가 있어요. 코드도 받으면 편합니다.
1. **Authentication → Emails**(또는 Email Templates) → **Magic Link**
2. 본문 아무 곳에 아래 줄을 추가하고 저장
   ```html
   <p>로그인 코드: <b>{{ .Token }}</b></p>
   ```
3. 이제 로그인 화면의 "코드로 로그인" 칸에 숫자를 입력해도 로그인됩니다.

## 6단계 — 환경변수 넣기 (GitHub ↔ Supabase 연결)

홈페이지가 어느 데이터베이스를 쓸지 알려주는 단계예요. 값 2개를 복사해서 GitHub에 붙여 넣습니다.

### 6-1. Supabase에서 값 복사
1. Supabase 왼쪽 아래 **Project Settings**(톱니바퀴) → **Data API** (또는 **API**)
2. **Project URL** 복사 → 예) `https://abcdefgh.supabase.co`
3. **Project Settings → API Keys** 에서 **anon public** 키(`eyJ...` 로 시작하는 긴 글자) 복사
   - 화면에 **Publishable key**(`sb_publishable_...`)만 보이면 그걸 복사해도 됩니다.
   - ⛔ **service_role / secret 키는 절대 쓰지 마세요.** (모든 보안을 무시하는 비밀 키입니다)

### 6-2. GitHub에 붙여넣기
1. GitHub 저장소 → **Settings** → 왼쪽 **Secrets and variables** → **Actions**
2. **Variables** 탭 → **New repository variable**
   | Name | Value |
   |---|---|
   | `SUPABASE_URL` | 6-1에서 복사한 Project URL |
   | `SUPABASE_ANON_KEY` | 6-1에서 복사한 anon(또는 publishable) 키 |
   두 개를 각각 **Add variable** 로 추가합니다. (Name은 대문자 그대로!)
3. **Actions** 탭 → 왼쪽 **홈페이지 배포** → **Run workflow** → **Run workflow**
4. 초록 ✅ 가 뜨면 홈페이지를 새로고침(Ctrl + F5)합니다.
   - 바닥글의 빨간 **DEMO** 표시가 사라졌다면 연결 성공!
   - 아직 콘텐츠가 없어서 "아직 준비 중인 자료실" 이라고 나오면 정상입니다.

> ❓ **anon key가 홈페이지에 드러나도 괜찮나요?**
> 네. anon key는 "이 데이터베이스에 접속하겠다"는 **공개용 주소표** 같은 것이라 원래 공개되는 값이에요.
> 누가 무엇을 수정할 수 있는지는 4단계에서 만든 **서버의 보안 규칙**이 로그인한 이메일을 보고 결정합니다.

## 7단계 — 첫 로그인, 기본 콘텐츠 넣기

1. 홈페이지 주소 뒤에 `admin` 을 붙여 접속합니다.
   ```
   https://내아이디.github.io/저장소이름/admin
   ```
   (자동으로 `.../#/admin` 으로 이동해요. 바닥글의 **편집자 로그인** 을 눌러도 됩니다.)
2. 4단계에서 적은 **내 이메일** 입력 → **로그인 메일 받기**
3. 메일함에서 Supabase가 보낸 메일의 링크를 **같은 브라우저에서** 누릅니다.
   (또는 메일 속 6자리 코드를 입력 — 5단계 선택 설정을 한 경우)
4. 관리자 페이지가 열리면 **[기본 콘텐츠 넣기]** 버튼을 누릅니다.
   → 메인·등장인물·시리즈·갤러리·로그 페이지와 예시 내용이 생깁니다.
5. 이제 모든 것을 관리자 페이지에서 바꿀 수 있어요! 🎉

## 8단계 — 다른 사람에게 편집 권한 주기

### 방법 A — 관리자 페이지에서 (추천)
1. 관리자 페이지 → **편집자 관리**
2. 친구의 이메일 입력 → 권한 선택 → **추가**
   - **편집자**: 글·이미지·디자인·메뉴 등 모든 콘텐츠 수정 가능
   - **관리자**: 편집자 기능 + 다른 사람의 편집 권한 추가/삭제
3. 친구에게 `.../admin` 주소를 알려주고, **그 이메일로** 로그인하라고 하면 끝!

### 방법 B — Supabase에서 직접
Supabase → **Table Editor** → `editors` 표 → **Insert row** → `email`(소문자), `role`(`editor` 또는 `admin`) 입력 → Save

> 목록에 없는 이메일로 로그인한 사람은 **Viewer**(보기 전용)입니다. "편집 권한이 없어요" 화면이 나오고, 어떤 것도 수정할 수 없어요.
> 권한을 빼려면 편집자 관리에서 **권한 삭제**를 누르세요. (관리자는 실수 방지를 위해 자기 자신은 지울 수 없어요)

## 9단계 — 링크 공유하기

- 방문자용: `https://내아이디.github.io/저장소이름/`
- 편집자용: `https://내아이디.github.io/저장소이름/admin`
- 특정 페이지: 그 페이지를 연 상태의 주소창 주소를 그대로 복사하면 됩니다.
  예) `https://…/저장소이름/#/p/series`

방문자는 로그인 없이 모든 공개 콘텐츠(메인, 등장인물, 시리즈, 갤러리, 로그)를 볼 수 있어요.

## 관리자 페이지 사용법

| 메뉴 | 할 수 있는 일 |
|---|---|
| **대시보드** | 전체 바로가기, (처음) 기본 콘텐츠 넣기 |
| **사이트 정보** | 사이트 제목, 사이트 설명, 머리글 작은 문구, 바닥글 문구 |
| **디자인** | 메인·보조·포인트·배경·글자 색상 (색상 선택기), 빠른 색 조합, 제목/본문/타자기/손글씨 글꼴, 배경 이미지, 격자·노이즈 효과, 종이·장식 기본 목록 |
| **메인 화면** | 구역(대표 이미지 / D-Day / 음악 / 두 캐릭터 / 캐릭터 이동 공간 / 편집자의 말) 켜고 끄기·**끌어서 순서 변경**·크기, 대표 이미지, D-Day 시작일, 음악 링크·제목, 캐릭터 프로필 사진·이름·소개·SD 이미지, 캐릭터 이동 공간의 걷기 이미지·타일·장식 |

### 페이지 종류
새 페이지를 추가할 때 종류를 고를 수 있어요. 같은 종류를 여러 개 만들어도 됩니다. (예: 갤러리 2개)

| 종류 | 기본 페이지 | 편집 방법 |
|---|---|---|
| **기록철 (종이 꾸미기)** | 등장인물 | 페이지에서 **[✎ 편집 모드]** → 종이 위 요소를 끌어서 이동, 오른쪽 아래 빨간 점으로 크기 조절, 위쪽 빨간 점으로 회전. 요소를 누르면 설정 창(글 내용·글꼴·크기·색·액자·레이어·복제·삭제). 빈 곳을 누르면 종이 설정(+글상자 / +사진 / +장식, 종이 배경·비율). **[+ 종이 추가]**, 종이 ←→ 순서, ✕ 삭제. 다 하면 **[저장]** |
| **DVD 선반 (시리즈)** | 시리즈 | **[+ 새 시리즈 추가]** → 제목·부제·연도·소개·DVD 표지·케이스 색·글자 색 + 상세 본문. 목록에서 끌어서 순서 변경 |
| **갤러리** | 갤러리 | 분류(로그·커미션 등) 추가/이름 변경/삭제/순서 변경. 이미지 **여러 장 한 번에 끌어다 놓기**, 설명 수정, 끌어서 순서 변경, 다른 분류로 옮기기, 삭제 |
| **로그 (블로그)** | 로그 | **[+ 새 글 쓰기]** → 제목·날짜·대표 이미지·요약 + 본문 |
| **자유 글 페이지** | (새로 만들 때) | 제목·설명·대표 이미지 + 본문 |

### 본문 편집기 (시리즈 상세·로그·자유 페이지)
- 블록 사이의 **+ 글 / 소제목 / 사진 / 사진 2장 / 인용 / 구분선** 을 눌러 원하는 위치에 추가
- `⋮⋮` 손잡이를 끌거나 ↑↓ 로 순서 변경, ✕ 로 삭제
- 사진 파일을 편집기 위로 끌어다 놓으면 맨 아래에 사진 블록이 생겨요
- 글 서식: `**굵게**`, `*기울임*`, `~~취소선~~`, `[링크 글자](https://주소)`
- **저장**을 누르면 반영돼요. (다른 화면으로 이동하면 자동 저장도 됩니다)

### 캐릭터 이동 공간 (메인 화면)
- 기본값으로 **낑냐마을** 리소스(`assets/stage/`)가 들어 있어요: `player1/2` 걷기 시트, 잔디·길 타일, 나무·덤불·바위·그루터기, 꽃·버섯, 그림자, 나뭇잎.
- 두 캐릭터가 알아서 상하좌우로 걷다가, 가까워지면 서로 바라보며 콩콩 뛰고 하트가 나와요. (방문자가 조작하는 게임 요소는 없어요)
- 새 캐릭터 그림으로 바꾸려면: **메인 화면 → 캐릭터 이동 공간 → 걷기 스프라이트 시트 → 업로드**
  - 시트 규칙: 가로 = 걷는 동작 칸들, 세로 = 방향 줄. 기본은 한 칸 16×24px, 4칸, 줄 순서 `down,up,left,right`
  - 칸 크기·칸 수·줄 순서가 다르면 같은 화면에서 숫자만 바꾸면 됩니다.
- 타일·나무·장식도 **배경 타일 · 나무 · 장식 이미지 바꾸기** 에서 추가/삭제/기본값 복원이 가능해요.
- 도트 이미지는 흐려지지 않도록 **원본 그대로** 업로드됩니다.

### D-Day
시작일(기본 2026-08-10)이 **D+0**, 다음 날이 **D+1** … 방문자 기기의 오늘 날짜로 자동 계산돼요. 자정이 지나면 새로고침하지 않아도 1분 안에 바뀝니다.

### 음악
YouTube · Spotify · SoundCloud 링크, 또는 mp3 파일(업로드 가능)을 쓸 수 있어요. 브라우저 정책상 자동재생은 되지 않고, 방문자가 ▶ 를 눌러 재생합니다.

## 이후 홈페이지를 수정하는 방법

### 내용·디자인 수정 → 관리자 페이지에서 (코드 수정 X)
글, 이미지, 메뉴 이름, 페이지 추가/삭제, 색상, 글꼴, 메인 구성, 캐릭터 이미지 등 **거의 모든 것**은 관리자 페이지에서 바꾸고 [저장]하면 **즉시** 반영됩니다. 배포를 다시 할 필요가 없어요.

### 코드 자체를 바꾸고 싶을 때 (드물게)
1. GitHub 저장소에서 바꿀 파일을 클릭 → 오른쪽 위 ✏️ (Edit this file)
2. 수정 → **Commit changes**
3. 1~2분 뒤 자동으로 다시 배포됩니다. (Actions 탭에서 진행 상황 확인)
4. 홈페이지에서 **Ctrl + F5** (휴대폰은 새로고침 여러 번)

여러 파일을 한꺼번에 바꿨다면 **Add file → Upload files** 로 같은 위치에 덮어써서 올려도 됩니다.

### 내 컴퓨터에서 미리보기 (선택)
`index.html` 을 더블클릭하면 보안 정책 때문에 열리지 않아요. 미리 보고 싶다면:
1. [VS Code](https://code.visualstudio.com) 설치 → 확장(Extensions)에서 **Live Server** 설치
2. `archive-home` 폴더를 VS Code로 열고 `index.html` 우클릭 → **Open with Live Server**
3. `config.js` 가 비어 있으면 데모 모드로 열려요. 실제 DB로 보고 싶으면 `config.js` 에 6단계 값 2개를 직접 넣고,
   5단계의 Redirect URLs에 `http://127.0.0.1:5500/` 도 추가하세요. (GitHub에 올릴 때는 `config.js` 를 비워둬도 Actions가 채워줘요)

## 보안은 어떻게 지켜지나요?

- 코드 안에 **관리자 비밀번호나 관리자 이메일이 없습니다.** 비밀번호 자체가 없고, 이메일 로그인만 써요.
- 로그인하면 Supabase가 "이 사람의 이메일은 ○○" 라는 **서명된 출입증(토큰)** 을 줍니다.
- 저장·수정·삭제 요청이 오면 **Supabase 서버**가 출입증의 이메일이 `editors` 표에 있는지 확인하고, 없으면 거절합니다. (`schema.sql` 의 Row Level Security 규칙)
- 그래서 누군가 브라우저에서 코드를 조작해 관리자 화면을 띄우더라도 **실제 저장은 불가능**해요.
- 방문자는 모든 공개 콘텐츠를 **읽기만** 할 수 있고, `editors` 표(이메일 목록)는 편집자만 볼 수 있어요.
- 이미지 저장소도 같은 규칙: 보기는 누구나, 올리기·지우기는 편집자만.
- ⛔ Supabase의 **service_role(secret) 키는 절대 GitHub이나 `config.js` 에 넣지 마세요.**

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 바닥글에 **DEMO** 가 계속 보여요 | 6단계 Variables 이름(`SUPABASE_URL`, `SUPABASE_ANON_KEY`)을 대문자 그대로 넣었는지 확인 → Actions에서 **Run workflow** 로 다시 배포 → Ctrl + F5 |
| "데이터베이스에 연결하지 못했어요" | Project URL/키를 잘못 복사했는지 확인. 4단계 schema.sql 을 실행했는지 확인. Supabase 프로젝트가 일시정지 상태인지 확인 |

| 로그인했는데 "편집 권한이 없어요" | 그 이메일이 `editors` 표에 있는지 확인 (소문자로). 추가 후 새로고침 |

### 참고 이미지와 저작권
디자인 참고용으로 주신 이미지(메인화면·캐릭터란·시리즈란 참고 이미지)는 다른 작가의 작품이라 **공개 저장소에 넣지 않았어요.** 색감과 분위기만 참고해 새로 디자인했습니다.
`assets/paper` 의 종이 2장과 `assets/deco` 의 장식은 이 프로젝트용으로 새로 만든 것이라 자유롭게 써도 됩니다. `assets/stage` 는 낑냐마을 게임 리소스입니다.
